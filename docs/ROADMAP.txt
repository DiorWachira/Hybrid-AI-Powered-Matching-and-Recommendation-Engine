TRAINING RUN RESULTS (local, 2026-09-20, recalibrated labels)
====================================================================
Run headlessly via nbclient on the local venv (torch 2.14.0+cpu), not Colab.
Historical reported results only; not rerun during this audit. Serving uses
different skill/growth formulas, so these metrics do NOT certify API scores.
Artifacts: data_pipeline/artifacts/hybrid_match_weights.json
Evidence:  data_pipeline/reports/overfitting_diagnostics.png
           data_pipeline/reports/test_evaluation.png
Data:      800 candidates x 100 jobs -> 4,000 pairs
Splits:    1920 train / 640 val / 640 warm test / 320 cold test

Read every accuracy against the Bayes ceiling of 0.799, not against 1.0,
and against a majority-class floor of ~0.50.

Warm test (unseen candidates, seen jobs), threshold 0.37:
  precision 0.663 | recall 0.931 | F1 0.774 | ROC-AUC 0.834
  accuracy 0.719  -> 90% of the Bayes ceiling; captures ~73% of the
                     available signal between floor and ceiling
  NDCG@3 0.910

Cold start (unseen jobs AND unseen candidates):
  precision 0.682 | recall 0.908 | F1 0.779 | ROC-AUC 0.799
    warm->cold F1 change: +0.004 in this synthetic experiment. This does not
    establish real-world generalisation or independence from model selection.
  CAVEAT: the cold precision@3 / recall@3 / NDCG@3 all read 1.000 because
  most cold candidates have <= 3 held-out jobs, making top-3 degenerate.
    Do not quote the cold ranking metrics. Classification metrics also need
    independent split/provenance review before being used as quality evidence.

Baselines (thresholds now tuned on validation, same as the learned model):
  fixed-weight rule (0.45/0.40/0.15): F1 0.747 | ROC-AUC 0.810
  BERT-similarity only:               F1 0.688 | ROC-AUC 0.691

Learned coefficients on standardised features (C=0.03):
  S_bert 0.770 | S_graph 0.681 | S_growth 0.793

Two findings worth reporting:
 1. The three signals now contribute almost equally. In the circular-label
    run the ordering was S_growth 4.24 >> S_bert 0.63, i.e. text was nearly
    irrelevant. Once job/CV text carried real specialisation signal, semantic
    similarity became as important as skill-graph overlap -- direct support
    for the hybrid design rather than a graph-only or keyword-only engine.
 2. BERT-only ROC-AUC rose from 0.605 (near chance) to 0.691 purely from
    enriching the generated text, confirming the earlier diagnosis that
    templated descriptions, not the model, were the bottleneck.

The learned model beats the fixed-weight baseline by +0.027 F1 and
+0.024 ROC-AUC -- a modest, believable margin, unlike the inflated gap the
circular label produced.

    LABEL-VALIDITY CORRECTIONS (blocking any quality claim in the report):
    HISTORICAL LOCAL implementation, not a verified Colab re-run. Synthetic
    latents reduce direct circularity but do not create independent gold labels.
[x] Replace the circular weak label. generate_synthetic_data.py now emits
    hidden latents (latent_competence, latent_adaptability on candidates;
    latent_quality_bar on jobs) that are never model features, and the
    notebook samples is_match as a Bernoulli outcome from a logit built
    from observable signal + those latents + Gaussian noise. Every driver
    is centred on its own mean, and the weights were calibrated empirically
    rather than guessed. Measured over the 4,000 pairs:
        quantity                                   old      new
        positive rate                              0.644    0.502
        best 2-threshold rule over own features    0.975    0.694
        Bayes accuracy ceiling                     ~1.00    0.799
    So results are now read against a ~0.80 ceiling and a ~0.50 floor,
    with a ~0.30 usable band, instead of against a label the model could
    simply reconstruct.
[x] Re-tune the baseline thresholds on the validation split, exactly as
    the learned model's threshold is tuned (shared tune_threshold helper;
    the old flat 0.5 cut-off made the fixed-weight baseline a near-constant

RISK WATCHLIST
====================================================================
 - Dataset access: BrighterMonday scraper runs cost money and are capped
   per run; keep the synthetic generator as the default path and treat
   scraped jobs as an enrichment, not a hard dependency.
 - Model size vs. latency: a large BERT model on CPU may breach the
   2-5 s target; pre-compute embeddings and consider a smaller model.
 - Python 3.14 compatibility: torch/transformers wheels may lag; be
   ready to run the backend on a 3.12 environment if installs fail.
 - Current primary blockers: feature-contract mismatch, unavailable live stack,
     security/abuse controls and independent evaluation evidence.
 - Free hosting: Oracle capacity/card verification/idle reclaim can block use;
     stay within Always Free limits and stop if any resource requires payment.
 - Neo4j ontology breadth: seed only the skill families needed by the
   demo domains (software, data, accounting).
 - Marketplace scope creep: apply/accept/contract/project/milestone/
   payment features stay in docs/extras/marketplace_features.txt and
   are out of this roadmap until the core engine is done.
