FIRST TRAINING RUN RESULTS (Colab, 2026-09-20)
====================================================================
Artifacts: data_pipeline/artifacts/hybrid_match_weights.json
Evidence:  data_pipeline/reports/overfitting_diagnostics.png
           data_pipeline/reports/test_evaluation.png
Data:      800 candidates x 100 jobs -> 4,000 pairs (2400/800/800 split)

Test metrics (learned logistic regression, threshold 0.40):
  precision 0.935 | recall 0.929 | F1 0.932 | ROC-AUC 0.979
  precision@3 0.812 | recall@3 0.800 | NDCG@3 0.992
Baselines:
  fixed-weight rule (0.45/0.40/0.15): F1 0.772 | ROC-AUC 0.859
  BERT-similarity only:               F1 0.745 | ROC-AUC 0.605

Overfitting check: PASSED. At the selected C=1.0 the train/CV-validation
accuracy gap is ~0.0007 (0.9186 vs 0.9179) and the learning curve has
converged, so the model is bias-limited, not variance-limited. There is
no overfitting; if anything the linear model underfits the label rule.

*** CRITICAL CAVEAT -- THESE METRICS DO NOT MEASURE MATCHING QUALITY ***
The training label is currently defined as
    is_match = (S_graph >= 0.6) AND (years_experience >= required_years)
S_graph is itself one of the three input features, and S_growth encodes
experience_fit, so the label is very close to a deterministic function of
the model's own inputs. Verified empirically on all 15,996 same-role
pairs: a hand-written two-threshold rule using only the model's own
features reproduces the label with 97.5% accuracy, which is BETTER than
the trained model's 92.1% test accuracy. The model is therefore
rediscovering the labelling rule, not learning to predict placement
success. The 0.979 ROC-AUC must NOT be reported as evidence of matching
accuracy. The learned coefficient ordering (S_growth > S_graph >> S_bert)
is likewise an artifact of the label definition ignoring text entirely,
not a finding about which signal matters in real hiring.
Corrective tasks are listed under Week 7 below.

RISK WATCHLIST
====================================================================
 - Dataset access: BrighterMonday scraper runs cost money and are capped
   per run; keep the synthetic generator as the default path and treat
   scraped jobs as an enrichment, not a hard dependency.
 - Model size vs. latency: a large BERT model on CPU may breach the
   2-5 s target; pre-compute embeddings and consider a smaller model.
 - Python 3.14 compatibility: torch/transformers wheels may lag; be
   ready to run the backend on a 3.12 environment if installs fail.
 - Scope creep on the frontend theme: keep Week 3 shells minimal and
   defer all styling to Week 7.
 - Neo4j ontology breadth: seed only the skill families needed by the
   demo domains (software, data, accounting).
 - Marketplace scope creep: apply/accept/contract/project/milestone/
   payment features stay in docs/extras/marketplace_features.txt and
   are out of this roadmap until the core engine is done.
